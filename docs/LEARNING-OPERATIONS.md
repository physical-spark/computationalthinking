# Profiles, sequential learning and prose publication

Students with a connected Google identity must save full_name, birth_date and one of the 100 avatar IDs or an uploaded photo before course or learning APIs are available. Existing rows remain nullable until the student fills the form. Administrators are exempt and remain outside groups. Legacy nicknames, identity IDs, Google subjects, drafts and progress remain untouched. Birth date is returned only to self and administrator profile endpoints, and excluded from CSV and browser persistence.

The server computes access independently for the Python and Module 1 tracks. Reading is freely accessible. Previously passed later steps stay accessible, but the first missing exercise must be completed before other new exercises unlock. Browser POST /attempts returns 409 and cannot create progress. Each authenticated execution gets a server UUID tied to learner, code, step and grading version. Only the private execution broker supplies its outcome. Output prediction submissions must reference this receipt and its owner. Completion is idempotent and per-learner serialized. Changing steps resets the sandbox; continuing in the same shell retains variables. Reload after deployment if an older tab requests client-side completion.

Administrator learning preview runs without recording views, attempts, drafts or reflections. The ?student=ID route uses the same renderer with the selected student's access/progress/code and disables execution and mutation; it does not impersonate that student's session. Explicit code-copy opens the administrator's own preview.

The content editor lists stable prose block IDs. Lesson prose and hints accept a restricted HTML vocabulary; short labels/concept/resource strings use plain text. Code, table, quotation and separator blocks are immutable, and existing heading structure/classes are preserved. Drafts remain private until published. Revisions append with author/time and base fingerprint. Restoring saves and publishes another revision. A Git-base conflict preserves the existing publication, rejects stale publication and requires a new draft based on the current baseline. Content text_version is separate from the grading version; prose edits do not reset passes. DB backup includes editorial revisions.
